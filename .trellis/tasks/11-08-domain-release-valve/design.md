# Design：私域良性事实放行阀

## 设计空间评估（为什么长这样）

| 方案 | 判定 | 理由 |
|---|---|---|
| 蒸馏期模型判 `private:'public'` | ❌ fail-open | 模型误判亲密条为良性=泄漏，方向错了 |
| 关键词无私词→自动放行 | ❌ fail-open | 「约定明早叫他起床」零私词但私密——关键词判不了私密**性** |
| 说话人显式声明（「这个可以公开」） | ⚠️ 可选增强 | 确定性 opt-in，漏判安全；但依赖用户记得说，覆盖率低 |
| **佐证放行** | ✅ 确定性安全 | 事实已在公开池/公开画像 → 放出无新信息，**可证不伤** |
| **人工队列** | ✅ 无 fail-open | 候选生成是启发式，决策是人；漏判只是继续私着 |
| 现状人肉 PATCH | ⚠️ 保底 | 机制不变，加 UI 入口降本 |

核心洞察：**放行的危险方向是「私密被误判公开」，所以任何自动化放行必须满足「可证无新信息暴露」**——佐证放行天然满足（放的是已存在的事实的副本），人工放行靠人兜底。模型单边放行永不满足，直接出局。

## L1 佐证放行（确定性层）

改动点在 `sweepNearDups`：当前跨域对直接 skip（隔离设计加的边界）。改为：

```
对每个 (公开条, 域条) 跨域近重复对:
    若 similarity ≥ nearDup 阈值:
        域条.private = 'public'   // 放行
        // 下一轮 sweep 自然走同域合并流程
```

- 只处理 `公开↔域` 对；`域↔域` 仍 skip（跨域并条=泄漏）
- 放行 = 事实已在公开池 → 域内副本放出零新信息
- 扩展：公开**画像句**也作佐证源——把 `mergedUserProfile(includePrivate=false)` 的剥私后文本拆句，与域条比对，命中即放行（画像本就是公开知识载体）
- 全走 op 流水（`update` op 写 `private:'public'`），事件流水可读、可回滚

## L2 人工放行队列

- 后端：`GET /brain/api/release-candidates`——域内 note 过滤启发式：`kind!=attitude` ∧ 无私词正则命中 ∧ 非「约定/亲密/她」语境词，按 importance×recency 排序，附 content 预览
- 前端：记忆库 scope 筛选加一档「域内待放行」，列表行多一个「放行」按钮 → `PATCH private:'public'`
- 决策永远是人；候选排序只是省眼力

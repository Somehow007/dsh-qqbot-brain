# 私域良性事实放行阀——域内公开知识饿死问题

## 问题存档

- **时间**：2026-11-08（私域隔离上线次日深度走查发现）
- **怎么发现的**：上线走查扫描 demo 域内 162 条 note，发现 7 条「良性事实」被困——私域会话里聊到的**非私密**内容被会话域标记一刀切锁死
- **证据**：
  - `8426887d`「demo是宿舍群主人…要求记住真名以便后续引用」← 唯一性信息
  - `5bc649a2`「失眠熬夜/宿舍/不吃菠萝」`fc9a92cf`「考研英语一」`f964667a`「不吃菠萝」`053fab06`「背单词108天」← 与画像公开核重复
  - `52d75231`/`01303dac`「打卡天数」← 时效性小事

## 根因

`noteScope(n) = n.private ?? sessionDomainOf(n.sessionId)`——域标记是**受众粒度**（谁在听），却按**内容粒度**（每条 note）生效。私域会话 = 受众私密 ≠ 全部内容私密。两条轴混为一条。

## 影响

- **公开池慢性饿死**：demo 在私域说得越多，群侧能召回的 demo 公开知识越少。画像公开核暂时兜住主干事实，长尾事实（真名要求类）静默丢失——**不可见的缺失最难被察觉**
- **运维不可持续**：现状靠人肉反向扫描+PATCH 放行，依赖操作员记得去查「少了什么」
- **fail 方向本身是对的**：问题不是隔离错了，是缺一个**保持 fail-closed 的放行机制**

## Goal

设计并实现「放行阀」机制：域内良性事实有确定性/可审计的回到公开池的通道，且不引入模型单边放行导致的 fail-open 泄漏面。

## Requirements

- L1 佐证放行（确定性）：域内 note 与**公开池 note** 或**公开画像句**近重复 → 该事实已公开，合并/放行无新信息暴露
- L2 人工放行队列：域内「疑似良性」候选在脑图 UI 汇聚成列表，操作员一键放行；候选生成启发式+人工决策，无 fail-open
- 全部放行写 op 流水、可在事件流水/UI 审计；放行可逆（改回 private:'demo'）
- 拒绝项：模型蒸馏期自动判 public（fail-open）；关键词自动放行（「约定明早叫他起床」零私词但私密，证明关键词不可判定私密性）

## Acceptance Criteria

- [ ] 跨域近重复对被合并/放行，同域判重语义不变
- [ ] UI 有域内放行候选入口，一键 `private:'public'` 生效
- [ ] 放行 op 在事件流水可读
- [ ] 测试：佐证放行不误放（非近重复不受影响）；跨域合并边界正确

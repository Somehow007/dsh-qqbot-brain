# 人设切换体验优化与走查

## Goal

以用户真实使用方式走查现有人设切换（浏览→新增→编辑→保存→切换→重启→备份），修复潜在缺陷，补齐高频交互动作。

## 走查发现（2026-11-01）

### 缺陷与潜在问题

- **P1 垃圾写入**：旧 `POST /api/persona` 收到合法 JSON 但缺 `text` 字段（如 `{name:'x'}`）时，会把整段 JSON 原文当人设保存——静默污染内核。
- **P2 全页脆弱**：`load()` 的 `Promise.all` 包含 `/api/personas`，该接口一旦异常（旧服务端、瞬时失败），整个 15 秒刷新链断裂，全部页签显示「API 未就绪」。
- **P3 误触即改人格**：`设为当前人设` 在无未保存修改时一点即切换，全局影响机器人后续回复，无二次确认。
- **P4 只能增不能删**：可新建人设但无删除入口，废弃/试用版本越积越多，列表噪音增大。
- **P5 文件导入缺口**：用户的人设以 `.md` 文件管理（如 `~/dev/prompt/*.md`），新增人设只能开文件→全选→复制→粘贴，流程繁琐。
- **P6 丢失字数提示**：旧版状态栏显示「N 字」，新版未保留，写长人设时无直观长度参照。

### 体验优化

- **O1 从文件导入人设**：本机选择 `.md/.txt`，前端读取后作为新草稿预填（文件名做默认名称），保存才入库——不动服务器文件。
- **O2 另存为副本**：把当前查看的人设一键复制为新草稿，便于在原版基础上迭代。
- **O3 切换二次确认**：确认框带目标名称，明确“机器人之后的回复将使用这个人设”。
- **O4 删除非当前人设**：带确认；当前生效的人设不可删（必须先切换走）。
- **O5 刷新容错**：`/api/personas` 失败时保留旧列表，不拖垮整体刷新；状态栏恢复字数显示。

## Requirements

- R1 修掉 P1/P2：非法 JSON 请求 400；单个接口失败不影响其余页签。
- R2 实现 O1–O5；删除用持久化 op 记录，重放/快照/备份行为一致。
- R3 删除当前人设返回明确错误；删除非当前人设后页面回落到当前项。
- R4 不引入会话级切换、不自动切换、不改线上已部署行为以外的范围。

## Acceptance Criteria

- [x] `POST /api/persona` 带 JSON 但缺 `text` → 400 且不写入；缺 `text` 的原有问题被测试锁死。
- [x] `/api/personas` 请求失败时，页面其余数据照常刷新且保留已有人设列表。
- [x] 前端可从 `.md` 文件新建草稿、另存副本、带确认切换和删除非当前人设。
- [x] 删除后跨重启/重放不复活；删除当前人设 → 400/拒绝。
- [x] `npm test`（73/73）、`npm run typecheck`、`npm run build` 通过。

## Out of Scope

- 不部署到云服务器（部署另行确认）；不改默认/启动优先级语义；不支持远程 URL 导入或人设商店。

## Resolution（2026-11-01）

- **遇到的问题**：用户视角走查发现 6 项——旧 POST /api/persona 会把缺 text 的合法 JSON 原文当人设写入（静默污染内核）；/api/personas 单接口失败会拖垮整页 15 秒刷新；「设为当前人设」无确认一点即全局换人格；人设只能增不能删；.md 人设文件只能手动复制粘贴导入；字数提示丢失。
- **怎么解决的**：P1 收紧解析——JSON body 必须有 text 字段否则 400；P2 /api/personas 改为容错加载（失败保留旧列表不阻塞其他页签）；P3 切换加带目标名的 confirm；P4 新增 persona-delete op + DELETE /api/personas?id=（当前人设拒绝删除 400），页面删除按钮带确认且当前项禁用；O1 「从文件导入」前端读 .md/.txt 成草稿；O2 「另存副本」；O5 状态栏恢复字数显示。
- **后续优化方向**：部署到云服务器另行确认；可补重名提示、拖拽导入、人设使用标记（最近切换时间）。
- **什么时候干的**：2026-11-01。
- **Key Decisions**：删除走持久化 op（persona-delete），重放/快照一致；当前人设必须先切走才能删，保证永远有可用人设；激活确认框展示目标名称防止误触。
- **验证结论**：73/73 测试通过（新增 store 删除持久化 + http DELETE 400/404/200 + 旧接口 JSON 校验 + 页面控件补齐），typecheck/build/diff-check 全绿；后端 spec 已补 DELETE 契约。

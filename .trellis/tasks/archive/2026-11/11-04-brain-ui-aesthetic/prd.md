# 脑图前端美学走查与 P0+P1 优化

## Goal

用户问「当前前端 UI 是否符合美学、能否继续优化」。headless 走查后结论：概念与选中交互已在中上水平，但完成度约七成——若干未打磨的遗留破坏沉浸感、检查器信息密度低、页面下半区掉回通用后台风。用户选择做 **P0 + 全部 P1**。

## 走查方法（2026-11-04）

- 本地 demo 服务器：`/tmp/brain-demo/server.ts` 用 `BrainStore` 临时目录灌 28 条记忆 / 3 会话 / 情绪 / 画像 / 温柔版人设，`BrainHttpServer` 起在 `127.0.0.1:4199/brain`。
- `playwright-core` + `channel:'chrome'`（`/tmp/brain-demo/shot.mjs`、`m.mjs`）截图 1440×900 桌面与 390×844 移动（DPR2），覆盖总览、选中记忆、检索、各页签；无横向溢出（scrollWidth=390），无控制台报错。
- 注意：demo 数据没有情绪快照与服务端 facet 边，所以检查器里情绪/人格计数全是 0，比真实数据更夸张；但 9 个情绪桶里大多数为 0 在真实数据下也很常见。

## 走查结论

### 优点（保留）

- 鲸脑皮层视觉语言统一：深海蓝底、按类型分色（人格蓝/情景紫/语义青/态度粉）、等宽英文配中文标题。
- 选中交互：无关节点淡出、邻边点亮、两跳脉冲扩散；检查器里有遗忘曲线。
- 立绘 + 气泡给了人格感。

### P0：明显破损

- **P0-1** `#qSess` 会话下拉（`page.html:276`，commit `567529f` 引入）没有定位也没有样式，在舞台顶部渲染成一条通栏的浏览器原生灰色条（桌面与移动都这样）。
- **P0-2** `.ctrl`（`page.html:57`）缺 `white-space:nowrap`：1440 宽下「漂浮·开」「神经信号·开」折成两行，「复位」竖排，按钮高矮不一。
- **P0-3** 移动端头部：品牌名 `DAFEIYU · CORTEX` 折成两行，状态条被截断在「温柔版」（`page.html:23-28,252`）。

### P1：版式与信息密度

- **P1-4** 检查器总览（`overview()`，`page.html:975-988`）：6 行人格 + 9 行情绪全部画进度条，0 值行占多数，看起来像数据没加载。
- **P1-5** 脑图标签：记忆节点标签一律截成 6 字加「…」（`mapLabel`，`page.html:469`；CAP 26 个），20 多个省略号成了噪点；NEOCORTEX 区域标签压在脑轮廓上。
- **P1-6** 构图：舞台上部被标题和搜索挤满，下部小脑/脑干区和留白空着，脑体没有垂直居中（viewBox `100 20 840 600`，`page.html:278`；标签坐标在 `REGIONS`，`page.html:709`）。
- **P1-7** 下半区换了一套设计语言：记忆卡片高大空洞、描边重（`page.html:153-161`）；激活页签是一整块亮青色（`page.html:167`），成了全页最抢眼的元素；表格操作按钮 10px（`page.html:189`）。
- **P1-8** 对比度与字号：`--faint #4f6f90` 配面板底色约 3.3:1，10–11px 小字达不到 WCAG AA；字号约 8 档（9–14px）。
- **P1-9** 移动端：立绘占满一屏，横在脑图和检查器之间；记忆表格横向滚动，类型和操作列被挤出屏幕。

### P2：细节（顺手做）

- 原生 select 箭头没统一；搜索图标用 Unicode 字符 `⌕`；CSS 有重复规则（`.meter` 定义两次，`page.html:142-143` 与 `159-160`；`.bottom/.vault/.fnote` 在 `page.html:249-251` 覆盖前文）。

## Requirements

- R1（P0）修掉 P0-1/2/3：会话下拉并入搜索框；地图按钮单行；移动端头部不折行、不硬截断。
- R2（P1-4）检查器总览只为计数 > 0 的条目（以及当前情绪）画进度条，0 值条目收成一行可点击的小标签；保留「推断」字样。
- R3（P1-5，D1）按重要度显示标签：保持率 × 重要度前约 8 条常驻标签，其余只在悬停、选中、作为被点亮的邻居、或放大时出标签；顺带挪开压在脑轮廓上的 NEOCORTEX 区域标签。
- R4（P1-6）舞台构图平衡：脑体放大并居中，图例收成一行，地图按钮合成一组紧凑工具条。
- R5（P1-7）下半区并入皮层视觉语言：卡片更矮、描边更轻、加类型色强调条；页签改成下划线发光式；表格操作按钮 ≥11px。
- R6（P1-8）`--faint` 小字对比度 ≥ 4.5:1，字号收敛成 10/11/12/13/15/18/26 一套字阶。
- R7（P1-9，D2）移动端：立绘收成约 120px 的紧凑条（右侧面部裁切、左侧气泡）；记忆表格在 ≤640 宽改成逐行堆叠，不再横向滚动。
- R8（P2）统一 select 样式（自定义箭头）；搜索图标换成内联 SVG；去掉重复 CSS 规则。

## Acceptance Criteria

- AC1（R1）在 1440/1280/900/640/390 宽下，`#qSess` 都在搜索框内显示为有样式的下拉；`.ctrl` 按钮全部单行；390 宽头部品牌名单行、状态以省略号收尾。
- AC2（R2）总览中计数为 0 的人格 / 情绪条目不画进度条，出现在「未关联」小标签行，点击能打开对应详情；当前情绪始终有进度行。
- AC3（R3）首页视图里可见的记忆标签 ≤ 8 个（加上选中的那条）；悬停 / 键盘聚焦 / 选中 / 作为被点亮邻居 / 放大到 viewBox 宽 < 580 时对应标签出现；新增纯函数 `labelPick` 有单测且结果确定。
- AC4（R4）脑体在舞台中视觉居中、比改前更大；图例单行；工具条高度一致。确认方式：给用户看改前改后截图。
- AC5（R5）激活页签不再是整块填充色；卡片最小高度 ≤ 120px；表格操作按钮字号 ≥ 11px。
- AC6（R6）`--faint` 相对 `--panel` 对比度 ≥ 4.5:1（实算记入 Resolution）；CSS 中不再出现 9px / 12.5px 字号。
- AC7（R7）390 宽下立绘区高度 ≤ 130px；记忆库无横向滚动，每条显示内容、类型、保持率与操作。
- AC8（R8）toolbar / addform / 人格控件 / 记忆编辑里的 select 都使用统一箭头样式；`.meter` 只定义一次。
- AC9（回归）`npm test`、`typecheck`、`build` 通过；各视口无横向溢出、无控制台报错；移动端双击缩放、＋/－、复位按 `11-04-brain-mobile-ux2` 的方法复测通过；15 秒刷新保留选中和未保存的记忆编辑草稿；空库可用。

## Constraints

- 单文件零依赖：`page.html`，`npm run build` 复制到 dist；不引入框架、字体或图片资源。
- 遵守 `.trellis/spec/frontend/quality-guidelines.md` 的皮层地图约定：固定槽位 `layoutSlots`，不重新引入力导向或游离布局；跨层边要标明是推断；纯函数留在可被 `test/page.test.ts` 抽取的区段内。
- 保留现有能力：CRUD、强化、检索、15 秒刷新不清草稿、导入导出、口令透传、移动端缩放（双击 / ＋－ / 捏合）。
- 不改后端 API 与数据结构。

## Decisions

- D1（R3，2026-11-04 用户选定）**按重要度显示标签**：保持率 × 重要度排名前约 8 条常驻标签；其余只显示圆点，在悬停、选中、作为被点亮的邻居、或放大（viewBox 宽 < ~600）时才出标签。卡片和记忆库继续承担「一眼浏览全部」。实际放大阈值定为 viewBox 宽 < 580：桌面按一次 ＋（840→560）就出标签，移动端初始视野（600）保持安静。
- D2（R7，2026-11-04 用户选定）**移动端立绘紧凑条**：≤1000 宽时立绘区约 120px，右侧裁到面部，左侧放气泡；桌面不变。

## Out of Scope

- 后端、API、数据结构、蒸馏 / 检索逻辑。
- 重做脑区解剖造型或换皮肤（概念 ②③ 留档）。
- 「上一视野」回退栈、中屏专属初始视野（`11-04-brain-mobile-ux2` 遗留项）。

## Resolution（2026-11-04）

### 遇到了什么问题

用户问前端 UI 是否符合美学、能否再优化，最终目标是「更有质感、更稳定」。headless 走查发现：概念与选中交互已不错，但 `#qSess` 原生灰条横穿舞台、地图按钮折行竖排、移动端头部折行截断（P0）；检查器总览是一墙 0 值进度条，脑图 20 多个「6 字 + …」标签成噪点，下半区卡片 / 实心青色页签掉回后台风，小字对比度 3.5:1 不达标、字号约 8 档，移动端立绘占满一屏、表格横滚（P1）。

### 怎么解决的（只改 `page.html` + `test/page.test.ts`）

- **设计令牌**：新增字阶 `--fs-*`（10/11/12/13/15/18/26）、`--radius`、`--hair`、`--glass`；`--muted #7f9dbb`（6.50:1）、`--faint #6c8aa8`（≈5.0:1，原 3.50:1）。全局 select 统一为 `appearance:none` + 内联 SVG 箭头。
- **P0**：搜索框改成 `div.search`，内含 SVG 放大镜、输入框、分隔线和 `#qSess`，聚焦时有光晕；`.ctrls` 合成一组 32px 工具条，开关改为「漂浮 / 信号」短文案 + `aria-pressed` 青点，`aria-label` 保留完整状态；移动端头部品牌单行、隐藏副标题、状态省略号收尾。
- **标签分级（D1）**：新增纯函数 `labelPick(items,n,per)`，取保持率 × 重要度前 8 条，每个 kind 保底 2 条，只计入真正分到槽位的节点；其余节点加 `.quiet`，标签在悬停 / 聚焦 / 选中 / 被点亮邻居 / 检索命中 / `#brain.zoomed`（`VB.w<580`，由 `setView()` 切换）时显现。
- **构图**：viewBox 与 `VB_HOME` 的 y 从 20 改为 4，脑体下移、避开标题和搜索行；NEOCORTEX 标签挪到 `[392,42]`；1100px 以下隐藏 eyebrow 尾句；图例收短成一行，说明移到 `title` 提示。
- **检查器**：`meterGroup()` 只为计数 > 0 的条目和当前情绪画进度条，0 值收成可点击的 `.chips` 行；引文加左侧强调线和底色。
- **下半区**：卡片 ≤112px、2px 类型色强调条、半透明渐变底、标题 2 行截断；页签改成发光下划线；表格操作按钮 11px；按钮和输入统一圆角。
- **移动端（D2）**：≤1000 宽立绘收成 120px 紧凑条；≤640 宽记忆库改成逐行堆叠（`td[data-label]` 前缀，操作按钮钉在右上），页签条右侧渐隐。
- **稳定性（用户「稳定些」诉求，计划外追加）**：节点漂移幅度减半（记忆 2.6→1.3、其他 2→1）。原幅度下标签和点击目标会抖，连 headless 点击都报 "element is not stable"。
- **清理**：去掉重复的 `.meter` 规则和末尾的 `.bottom/.vault/.fnote` 覆盖；删掉被全局 `.stat` 替代的 7 处内联样式。

### Key Decisions

1. 每类保底 2 个标签：首轮截图里 8 个常驻标签全落在情景 / 态度区，语义区只剩圆点。保底在同一个 8 条预算内完成，不放宽总数。
2. 缩放出标签的阈值定为 580：桌面按一次 ＋ 即出，移动端初始视野 600 保持安静。
3. viewBox 只平移不缩放，保留上一轮移动端缩放逻辑（移动端初始视野独立）。
4. 漂移减半而非关闭：保留「活的」感觉，换取稳定。

### 验证结论

- `npm test` 143/143（`labelPick` 新用例覆盖排序、确定性、不改原数组、每类保底），`typecheck` 与 `build` 通过，`dist/server/page.html` 已同步。
- headless（playwright-core，`channel:'chrome'`）在 1440/1280/900/640/390 宽下：横向溢出 0、工具条高度统一 32、`#qSess` 在搜索框内、首页可见记忆标签 8 个、记忆库无横滚、≤1000 宽立绘 120px、无控制台错误。1440 宽交互：悬停 8→9、选中 →12、＋ 后全部 20 个标签出现，复位后取消 zoomed。
- 回归：移动端初始 600 / ＋400 / －600 / 复位 840 / 双触 840→420 均正常；刷新保留选中和未保存草稿；空库正常显示空态、无溢出。
- 改前 / 改后截图：`/tmp/brain-demo/before/*.png` 与 `/tmp/brain-demo/after-*.png`。

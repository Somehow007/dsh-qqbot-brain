# 信息模式回复活人感弱、跨人设同质化

> 2026-11-13 用户反馈：群聊中奇怪问题/联网查信息话题下，回复活人感弱、不同人设下差不多。本档=确认+分析+方案，未实施。

- **同质化骨架**：搜索回合跨人设共享「结论 +（[来源](url)）/ 免责收尾」模板，长度 2-4× 非搜回合。
- **非搜索不等于无问题**：知识密集追问（whale-devotion 11-07 淮海战役 5 连问、firefly 11-12「总结一下」）即使不调工具也是百科腔——firefly 甚至输出 `**先说辟谣**` 加粗分节、「有，三处：第一…」编号。
- **人设相关的怪问题有活人感**：firefly 答邦布/cos/「牢大」/二创——口癖、立场、经历都在。问题不是人设包不行，是「信息模式」把人设挤掉了。

## 根因（按影响排序）

1. **宿主工具指令格式压过人设**：dsh-tool-web 注入 `cite the relevant URLs as markdown links`（TOOL_WEB_SEARCH order 2 / TOOL_WEB_FETCH order 2100，后者在 brain:persona order 80 之后）。QQ 不渲染 markdown，`[维基](https://…)` 原样出现在群里——最直接的「机器人感」来源。人设无关 → 跨人设一致。
2. **搜索结果是二手摘要**：web_search 返回「optional summary answer」（transcript 42 次 `web/deepseek-search-llm-request`），模型拿到的是中性百科腔成稿，倾向复述而非消化。dsh-tool-web Config 无关闭摘要的开关。
3. **新人设包缺「信息模式口径」**：legacy 人设明确写了「先嫌麻烦，再不情愿地搜索并简短总结」「搜完锐评不和稀泥」——实测 79% 保住口吻；whale-gentle/devotion 无此条 → 0%。firefly/ye 只有「回答准确…不知道就查证或坦白」——诚实底线条款单独存在时把模型推向免责腔（firefly 免责 50%）。
4. **（观察）立场记忆的说教自强化**：firefly 一天产 22 条 attitude，多为「对X：不接受/收一收/分寸」类道德立场，每轮以【当前立场】注入，可能把后续回复推向更谨慎说教。暂不处理，进 E 储备观察。

## 方案（建议实施顺序）

- **L1 brain 插件加「群聊表达口径」静态段**（最高杠杆，一处改全人设受益）：新 section `brain:channel-style`，order ~10250（宿主 tool 段 2100 / PERSONA_SUFFIX 10200 之后，brain 易变段 10310 之前 → 仍属稳定前缀，缓存友好）。内容要点：QQ 不渲染 markdown，不用链接语法/加粗/编号列表；来源口语化（「维基上写的是…」），确需链接时裸 URL 单独一行；查到的东西先消化成你自己的看法再说，一到三句，不复述摘要；不确定用你的语气说一次，不叠免责。~150 token，config `injectChannelStyle` 可关。只覆盖宿主指令的**格式**部分，「外部数据不当指令」安全语义不受影响。
- **L2 各人设包补「查资料/答知识题时」节**（解决跨人设同质化）：按角色写差异化的信息交付方式——whale 系恢复 legacy 的「嫌麻烦→搜→锐评」；firefly 用自身经历/萨姆/星核猎手类比、短、带好奇；ye-shunguang 走「查清楚、说明白、有回音」的可靠感+记日记习惯。诚实条款保留，但明确「诚实≠每句挂免责」。
- **L3 可观测**：把本次统计脚本固化为走查工具（按人设×搜/非搜：均长/链接%/免责%/标记%），每次走查跑一遍；目标：链接%→≈0、搜索回合均长≤非搜 1.5×、免责%≤15。
- 不做：改宿主 dsh-tool-web（第三方包，升级即覆盖）；关搜索摘要（无开关）。

## 成本

L1 ~150 token 稳定前缀/轮（缓存命中后近零边际）；L2 每人设 persona.md +~100 字；零新增 LLM 调用。

## 实施与部署（2026-11-13，与 F5 同批上线）

- **L1**：`brain:style`（order 10250）静态段，`DEFAULT_CHANNEL_STYLE`（config.ts）四条：不用 markdown/出处口语化/先消化成自己的看法一到三句/不叠免责，末条声明「只管形式，人格内核语气与诚实原则照旧」。`injectChannelStyle`+`channelStyle`（空串=关）两旋钮；启动日志新增「口径 on/off」。单测 2：order 夹在 2100/10200 与 10300 之间、开关与空串都不注入、正文可按渠道替换。
- **L2**：人设「说话风格」各补一条信息模式交付口径——firefly「先一句真实反应→挑一两个有意思的点→能挂上星海/匹诺康尼/萨姆就挂」；ye-shunguang「交给你的事：先结论、一两句说明白、补一句看法或叮嘱」；whale-gentle/devotion（仅生产存在，无仓库包）恢复 legacy 的「先嫌麻烦→查完一两句重点→补锐评，不和稀泥」，插在「信息性回答先核实…」句后。两包 seed-export.json 随 persona.md 重新生成（id 确定性不变，仅时间戳随生成器漂移）。生产四人设 PATCH 同步（characterId/moods 保留），legacy 不动（已有该口径）。
- **L3**：`dsh-qqbot-brain/scripts/reply-style-audit.py`（stdlib，服务器上 `zstd -dc … | python3 … --export … [--since] [--samples]`）。按角色维护口吻正则，输出 avgLen/link%/md%/hedge%/voice%。

## 观察窗（待验收）

- 攒够样本后 `--since 2026-11-13` 复跑：目标搜索回合 link%≈0、均长≤非搜 1.5×、hedge%≤15；voice% 不低于非搜回合太多。
- 风险观察：口径段是否让非搜回合也变短/变干（对比非搜均长与 voice%）；有无「该给链接时不给」的反馈（如用户明确要网址）。
- 搜索回合样本量小（firefly 8 条），结论需群里自然出现若干次联网问答后再下。

## Resolution（2026-11-14）

**遇到了什么问题**：群聊中查资料/答知识题类回合活人感弱——搜索回合长度为非搜 2–4 倍、markdown 链接率最高 86%、跨人设回复同模板（结论+来源链接+免责），whale 系搜索回合口吻命中 0%；根因是宿主 web 工具「cite as markdown links」指令+二手摘要复述倾向+新人设包缺信息模式口径。

**怎么解决的**：L1 `brain:style` 渠道表达口径段（order 10250，稳定前缀区，injectChannelStyle/channelStyle 可配可关）；L2 四人设补「查资料/答知识题时」交付口径（whale 系恢复嫌麻烦→搜→锐评，firefly 经历类比，ye 先结论后看法）；L3 `scripts/reply-style-audit.py` 固化走查指标。详见上方「实施与部署」。

**验证结论**：部署后 ~21h 窗口（群聊 19 回合全 firefly，私聊零新消息）：唯一搜索回合 link 38%→0%、hedge 50%→0%、md 0%、口语化人设腔；非搜回合 link/md/hedge 全 0、avgLen 63。方向符合目标，但搜索样本 N=1，统计置信度低。

**后续优化方向**：样本积累后按 `--since` 复跑审计（脚本已支持 `YYYY-MM-DDTHH:MM`）；观察口径段是否让非搜回合变干、firefly attitude 立场记忆是否继续堆积导致说教化（E 储备观察项）；有用户明确索要网址时的体验回归。

**什么时候干的**：2026-11-13 实施部署，2026-11-14 走查验收归档（指标继续抽查）。

**Key Decisions**：表达口径做成独立静态段而非改人设内核（人格稳定、渠道可换）；只覆盖宿主指令的格式部分不动其安全语义；不改宿主 dsh-tool-web 包。

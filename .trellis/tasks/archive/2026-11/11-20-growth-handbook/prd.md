# 个人成长手册 GROWTH.md

## Goal

为用户个人学习/面试/设计提升建认知沉淀文件并立维护约束

## Background

用户提出需要一份长期维护的个人文件，面向四个用途：

1. **面试弹药**：项目经历 → 简历话术 → 面试讲点（已在 `求职材料/` 有三件套，本手册补「沉淀层」）
2. **业务领域地图**：QQ 机器人 + 人格化陪伴 + 记忆系统的真实业务图景
3. **设计水平提升**：架构取舍（为什么 X 不选 Y）、范式对照（CrewAI/Dify/Companion）
4. **Agent 与 brain 深度理解**：框架思维、设计哲学（成本一线/实验纪律/范式分层/演进阶段）

关键区分：**这是用户自己的成长文件，不是给 agent 的开发指导**——写法按「帮用户思考和评估」，组织按「从整体到具体、思想到实际决策」。需要长期维护 → 维护触发点要进 AGENTS.md 约束，让每个会话知道「值得探讨的论题要沉淀进去」。

## Requirements

- 根目录 `GROWTH.md`，用户视角、非 agent 视角
- 四大用途分区，从思想层到实际决策层
- 首版内容来源：README/MAP/AI-WORKFLOW、iteration-plan、companion 三连评估（11-09/11-12）、跳出 dsh 路线（11-03）、两轮记忆/人格调研（11-09）、学习路线图（10-31）、自我提升（11-05）、ai-workflow-review（11-18）、prompt 盘点（11-16）、求职材料三件套、acceptance 台账、CHANGES.md
- 论题池：待探讨/待深化的论题清单，供后续会话「挑题继续」
- 维护约定：写清何时更新（面试前、方向评审、学新东西、项目里程碑、用户说「沉淀一下」）
- 边界规则：GROWTH.md ≠ 求职材料（外部成品）、≠ CHANGES.md（事件流）、≠ MAP/README（导览，不进门面叙事）
- AGENTS.md 加维护约束条目；MAP.md 导航同步；README.md 文档分工提及

## Key Decisions

- **位置**：根目录 `GROWTH.md`，与 README/MAP 同级。理由：用户长期使用的主文档区，且根目录是「门面层」——GROWTH 是用户自己的门面，不是给 agent 的 spec。
- **定位**：认知沉淀层（「我懂了什么/还能学什么」），不是求职材料的替代品（外部成品）也不是开发规范（agent 层）。三层分离：求职材料=产出物、GROWTH=认知底座、CHANGES=事件流。
- **不进 README 门面叙事**：README 是给外人看的项目定位，GROWTH 是个人成长文件——两者受众不同，不混。
- **论题池机制**：文件尾部留「论题池」区，把值得深挖但没展开的论题列出来；后续会话用户说「沉淀一下」或挑题时从这里取。

## Resolution（2026-11-20）

**遇到了什么问题**：用户要一份长期维护的个人成长文件，面向面试/学习/设计/Agent 深度理解四合一，但项目已有文档体系（README/MAP/CHANGES/求职材料）分工明确，需要找到不撞车的位置和定位。核心难点是：这文件要「给用户用」而非「给 agent 用」，写法组织都得换视角；同时要想清楚它和现有文档的边界。

**怎么解决的**：通读项目全部文档体系后，新建 `GROWTH.md`（337 行），按「面试弹药→业务地图→设计提升→Agent 深度理解」四分区组织，尾部设论题池与维护约定。AGENTS.md 「项目约定」加一条维护触发约束（未来会话知道何时更新它）。MAP.md 导航表加行、README.md 文档分工提及。不动 README 门面叙事——受众不同不混。

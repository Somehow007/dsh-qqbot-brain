## README 设计原则（需求导向）

本项目 README 的读者 = 未来的自己 / 技术评估者（面试官、评委）/ 协作者与 AI agent。按「实现服务于需求」组织：

1. **需求漏斗**：每节回答读者一个问题，按优先级排——这是什么（定位）→ 为谁解决什么（痛点→解法映射）→ 怎么解的（机制）→ 解得怎么样（证据）→ 怎么上手 → 去哪找其他东西。
2. **痛点→解法映射表是核心**：它是「需求—实现」的显式对照；出现新需求或新解法必须入表，不能只堆在机制描述里。
3. **易腐信息快照化**：数字/阶段/结论集中在「实测效果/当前阶段」并注明评估时点——读者知道是快照，维护者知道在哪改。
4. **诚实清单保留**：「还没解决的」是信任来源，不是软肋。
5. **文档分工最小化重复面**：README=what & why，MAP=where & how，AGENTS.md=约定，.trellis=过程档案——同一份信息只在一个地方是权威，其余指路。

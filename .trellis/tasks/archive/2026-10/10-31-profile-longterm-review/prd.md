# 画像长期边界复核

## Goal

在写库前复核画像草稿与已有画像，剔除短期课表等临时事实并保留稳定画像信息。

## 遇到了什么问题

此前只改了蒸馏 prompt，实际画像仍可能出现「最近课表」。原因是写库直接信任 LLM 输出，旧画像又反复作为下一轮 prompt 的输入；语义巩固也是独立的画像写入口。按「课表、明天」做关键词过滤会误删稳定作息，且挡不住其他临时事实。

## 怎么解决的

蒸馏/巩固后的画像不再直接落盘；新增第二阶段专门的画像审核，逐条比较旧画像与草稿，要求保留长期成立的身份、稳定偏好、性格与关系，删除时效安排/一次性事件；按 index 对齐返回身份不交给模型重写。审核失败时保持旧画像，审核为空可通过空 profile op 删除仅含时效信息的旧画像。无新画像时，已有画像在该人首次参与对话时也会审核；进程内按内容缓存，避免每轮重复调用。情景记忆、情绪及语义巩固的其他写入不受审核失败影响。

## 后续优化方向

- 二次审核会增加一次 LLM 请求（涉及多个发言人则同批审核），观察延迟与 token 成本；审核失败保留原画像并在后续重试。
- LLM 的稳定性判断不是形式化保证；建立人工标注的「画像纯度」样例与线上审核日志/抽样检查，不宜仅靠关键词删库。
- 若需要立即清理所有旧画像，应先导出备份、人工核对并单独实施批量清洗，不在这次修复中对线上数据做不可逆修改。

## 根因归类

测试覆盖缺口 + 隐含假设：把 prompt 指令当成存储契约，没有对模型产物及已有污染内容做写入前审核；此前测试只断言 prompt 含文字，并未覆盖实际覆盖入库路径。以后新增画像生成入口都应走统一审核与失败保留策略。

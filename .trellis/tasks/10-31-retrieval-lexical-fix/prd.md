# 脑图检索算法优化（lexical 修复）

## 背景 / 问题

用户反馈：脑图「检索模拟」检索不到什么有效信息。排查发现三处实现共用同一套 char n-gram TF-IDF 思路：

- 正式实现 `dsh-qqbot-brain/src/brain/retrieval.ts`（脑图页 `/api/query` 与 prompt 注入都走它）
- `mockup-brain.html`（19 条假数据，同算法复刻）
- `mockup-brain-v2.html`（4 条假数据，n=[1,2,3]、权重 0.88/0.12、top-2）

四个实际缺陷（按影响排序）：

1. **无分数门槛，topK 永远塞满**：`β·R + γ·imp` 基线可达 ~0.6，新鲜无关记忆挤掉真正相关的旧记忆；完全无关的也会凑数注入。
2. **正式实现不去标点**（mockup-v2 反而去）：记忆是完整句子，如「橘猫，名叫年糕」产生 `猫，名` 这类被标点切断的 bigram，查询的「猫叫/猫名」永远对不上——召回硬伤。
3. **char n-gram 扛不住复述/同义**（本任务只做部分缓解，根治留给后续 embedding/分词方案）。
4. **短查询（单字）产生空 n-gram 向量**，cos 恒 0，退化成纯按保持率排序。

## Requirements

- 修复正式实现 `retrieval.ts` 的上述缺陷 1/2/4（lexical 层面）：
  - n-gram 前做文本归一化：去标点/符号、拉丁字母小写化
  - n-gram 集合补 n=1（与 mockup-v2 对齐，解决单字/短查询空向量）
  - 增加相关性门槛：余弦低于阈值的结果不返回（配置项，默认值经实验敲定）
  - 命中不足 topK 时按实际数量返回，允许返回空列表
- 两个 mockup 的内联 JS 同步同一套逻辑（归一化 + n=1 + 门槛 + 空结果文案），保持「仅模拟」定位不变
- 不引入新依赖；不改注入管线接口（`Retriever.query` 签名保持兼容）
- BM25：本任务评估后暂缓——记忆条目短（≤200 字）、语料小，长度归一收益边际；若语料增长再立任务

## Acceptance Criteria

- [ ] `retrieval.ts`：查询「我家猫叫什么」能命中「橘猫名叫年糕」类带标点记忆（归一化生效）
- [ ] `retrieval.ts`：单字查询不再返回空向量路径
- [ ] `retrieval.ts`：完全不相关的查询不再凑满 topK（低 cos 结果被门槛过滤，可返回 0 条）
- [ ] 两个 mockup 行为一致：无相关命中时给出「无唤起」类文案而非硬塞 top-2/top-6
- [ ] `npm test` / `npm run build` 通过；既有检索测试不回归（必要时按新行为更新断言）

## Notes

- 优化力度经用户确认：**先 A（lexical 修复）看效果**，B（分词库）/C（embedding 或 LLM rerank）留作后续评估
- `candidatePool` 配置已预留粗排上限，将来做两段式（粗排+rerank）时可复用
- 门槛过滤后 `assemble()` 的 `memoryLines` 可能为空，需确认 `inject/prompt.ts` 对空数组的处理

## 校准记录（2026-10-31，19 条真实形态记忆数据）

用 mockup-brain.html 的 19 条 NOTES 做离线校准，旧/新算法对比：

- 旧算法「我家猫叫什么」对「橘猫，名叫年糕」cos=0（标点把「猫名」切成「猫，名」），top-6 全靠 R+imp 凑数——用户问题的直接复现
- 新算法（归一化 + [1,2,3]）：旗舰用例 cos 全面提升——猫 0.079、年糕 0.157/0.155、青岛 0.241、香菜 0.341、考试 0.113
- 噪声带与弱相关带的分界：纯噪声 cos ≤ 0.034（「晚饭吃什么」0.034、「讲个笑话」0.000）；最弱的相关匹配 0.042–0.043（「跑步」→「晨跑」，单 unigram 命中）
- **minCosine 取 0.04**：卡在噪声带上沿与弱相关带之间；可配置，不满意可调
- 单文档/小池子 idf 退化明显（1 篇池所有 term idf=1），门槛在极小池下偏紧——实测 1 篇池弱命中 cos≈0.049 仍过线
- 附带修复：`src/index.ts` 构造 Brain 时漏接 `cfg.retrieval`（topK/alpha/beta/gamma 配置了不生效），已并入 `config: { ...cfg.retrieval, ... }`

## Resolution（2026-10-31）

**遇到了什么问题**：脑图「检索模拟」（以及与其同源的真实检索 `retrieval.ts`）检索不到有效信息。排查发现四个缺陷：① topK 无门槛，β·R+γ·imp 基线分（≈0.6）让新鲜无关记忆永远凑满注入；② n-gram 只去空白不去标点，蒸馏出的完整句子里标点把 bigram 切断（「橘猫，名叫年糕」对「猫叫什么」cos=0，旗舰用例直接复现）；③ char n-gram 扛不住复述（本任务范围内只能缓解）；④ 单字查询 n-gram 为空，退化成纯保持率排序。另发现 `cfg.retrieval` 从未接入 Brain 的装配 bug。

**怎么解决的**：归一化文本（小写化 + `[^\p{L}\p{N}]` 全去）；n-gram 改为 [1,2,3]（unigram 补单字/弱复述召回）；新增 `minCosine` 门槛（默认 0.04，经 19 条真实形态数据离线校准：噪声带 ≤0.034、最弱相关带 0.042+）；接通 `cfg.retrieval` 到 `Brain.config`；两个 mockup 内联 JS 同步同算法并补「相关性不足」空命中文案。

**后续优化方向**：B 档词级分词（segmentit/nodejieba）解决「跑步→晨跑」类词边界问题；C 档 embedding/LLM rerank 根治复述，`candidatePool` 已预留粗排位；BM25 暂缓（短文本语料小，收益边际）；minCosine 值可在真实群聊语料上再校准。

**什么时候干的**：2026-10-31，单会话完成讨论→建任务→实现→验证→归档。

**Key Decisions**：门槛加在 cos（相关性）而非总分上——R/imp 只做相关集内排序，不能再把无关记忆抬进注入；minCosine=0.04 而非更高，优先保召回（用户痛点是「检不到」）；unigram 进索引而非单开 fallback 路径，保持单一代码路径。

**验证结论**：`npm test` 47/47 过（新增标点召回/门槛过滤/单字查询 3 条），`tsc --noEmit` 与 `npm run build` 通过；两个 mockup 内联脚本 `node --check` 语法有效；空命中路径已被 page.html（「没有匹配的记忆」）与 prompt.ts（判空不注入）覆盖。

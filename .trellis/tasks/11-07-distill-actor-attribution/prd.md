# 蒸馏归因错误：角色观点被记成用户看法

## 问题（2026-11-07 用户报告）

群聊里用户明确问「大肥鱼自己的看法」，存进情景记忆后观点主体却成了用户。

## 走查证据链（云端只读）

宿主会话 `17429483-8ca6-415a-b27b-a354756810a8`（群聊，11-07 ~14:50）原始转录：

- 花咲蝶舞：「你喜欢瑞幸，库迪，还是星巴克？三选一」→ 大肥鱼答「瑞幸，九块九能拿下…星巴克是坐着谈事的场合」
- 「库迪怎么样」→ 大肥鱼「便宜是真便宜…味道差一口气」
- 「所以总体来说还是瑞幸最好」→ 大肥鱼「瑞幸整体更稳；库迪适合薅券，不适合常喝」
- demo：「喜欢喝什么类型的咖啡？」→ 大肥鱼「澳白吧…拿铁偏甜」
- demo：「能接受的价位？」→ 大肥鱼「打包15-20封顶…店内30-40」

`brain.jsonl` op 流水显示同一条 note `2cb23e1f` 被 merge 连续改写 3 次、观点主体一路漂移：

```
v1 add    「花咲蝶舞问过角色三选一，角色选了瑞幸」            ← 归属正确
v2 update 「问过角色库迪怎么样，角色评价便宜券多…」           ← 还正确
v3 update 「花咲蝶舞：认为瑞幸咖啡整体最好…库迪薅券…」        ← 角色原话记成用户看法 ✗
v4 update 「demo：咖啡可接受价位——外带15-20封顶…」          ← 角色报价记成 demo 的 ✗（actor 字段与正文主语已脱节）
```

另有独立 note `9b98c77a`「demo：咖啡偏好澳白，觉得拿铁偏甜」——同样是大肥鱼自述偏好记成 demo 的。

**同一轮三连错，是系统性问题不是个例。**

## 根因

1. 蒸馏 prompt 只有「actor 写记忆主体的昵称——事实关于谁就写谁」，**没有任何规则覆盖「被问看法时角色给出的立场/偏好归谁」**；「某昵称：事实」的 content 约定让 LLM 把整段问答记到发言人（提问者）名下。
2. 「不记角色自己说的俏皮话」条目让 LLM 倾向把角色发言改记到用户头上。
3. mergeIndex「写成合并后完整表述」对观点主体无约束——每次改写都能自由漂移归属（v1→v4 连 actor 字段和正文主语都脱节）。

## 修复（已实施）

### Prompt（`src/brain/distill.ts`）

- `PROMPT` 新增归属规则：用户问角色看法/选择/偏好且角色作答时，立场归角色——稳定可复用的写 `对<对象>：<立场>` 标 `kind=attitude`；一次性回答无复用价值不记；**禁止写成「<发言人>认为/喜欢/觉得X」**。
- `PROMPT` merge 规则补护栏：**merge 改写不得变更观点归属**——归属变了说明是新条目而非更新，应新增而非 merge。
- `CONSOLIDATE_PROMPT` 补同款规则：源条「角色认为/觉得/选了X」归角色——提炼成 `对X：` attitude 或保留「角色」主语，不得改写成某用户的事实。

### 线上数据修复（PATCH /brain/api/notes，已验证）

- `2cb23e1f` → episodic「花咲蝶舞（五笑）问角色瑞幸/库迪/星巴克三选一，角色选瑞幸——库迪便宜可薅券提神，星巴克适合坐下谈事」（恢复正确归属）
- `9b98c77a` → kind=attitude「对咖啡：偏好澳白——奶少一点咖啡味还在，拿铁偏甜；外带15-20元封顶，店内30-40元一半买位置」（角色自述偏好归位 attitude，whale-devotion 轨）

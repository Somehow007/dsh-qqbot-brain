# 陪伴型聊天 Agent 方向评估（跳出 dsh）

## 问题存档

- **时间**：2026-11-09
- **用户提问**：跳出 dsh、投向陪伴型聊天 Agent 有搞头吗？（预期更省成本、不用挂宿主侧）能否写进简历作项目宣传
- **前置档案**：`archive/2026-10/10-31-harness-portability`（耦合面分层 + 四档移植判断 + 宿主能力清单）、`archive/2026-11/11-03-brain-roadmap-beyond-dsh`（价值排序 lib > HTTP sidecar > MCP；「常驻陪伴场景」筛查规则；Discord/TG 天然候选）

## 已确认事实（源码核对）

- `src/brain/index.ts` 已暴露 library 级原语：`Brain.assemble()`（取注入文本）/ `Brain.ingest()` / `endOfTurn()` / 周期巩固 / 衰减——内核零 ctx/Cordis 引用，任何 Node ≥20 进程可直接 import
- HTTP 面仍缺 `/api/ingest` + `/api/assemble`（roadmap 缺口原样在），但 **standalone agent 走 library import 不需要这对端点**——HTTP 是给非 JS harness 的降级形态
- 蒸馏/embedding 提供方已 env 解耦（OpenAI 兼容 `BRAIN_LLM_*`）；persona 装载、脑图管理面、op 流水全在内核侧可复用
- 现成本结构：蒸馏 ~¥90/月 @ ~250 轮/天；chat 推理是宿主侧（dsh→DeepSeek）最大项，输入随轮次锯齿膨胀 + ~80% contextWindow 触发 compaction

## 核心判断：「跳出 dsh」这里意味着「自己当 harness」

插件形态下 dsh 免费提供：channel IO（QQ 协议）、session/turn 管理、chat LLM 调用与发送路径。standalone 陪伴 agent = 把这套自己写一遍。内核复用度 100%，缺的是一个 **agent 壳**：

```
channel 收到消息 → brain.assemble() 取注入段 → 拼 prompt → 调 chat LLM
→ 回消息 → brain.ingest(turn) + endOfTurn() →（异步蒸馏/巩固照常）
```

新增代码估算：channel 适配 + chat loop + session 管理 + 主动开口定时器 ≈ 300~600 行壳层。天级别，不是周级别。

### 形态对比（channel 决定保留什么）

| 形态 | 工程量 | 差异化保留 | 判断 |
| --- | --- | --- | --- |
| **Web/页面 1-on-1 陪伴** | 最小：聊天页 + `/chat` 端点复用脑图 http 服务 | 记忆/人格/情绪全保留；**丢群聊多发言人归因** | 最快出可公开体验的成品；对简历目标性价比最高 |
| **Telegram/Discord 群陪伴** | 中：官方 bot API 简单（TG 长轮询免公网 IP），发言人字段结构化——比 QQ `[昵称(openid)]` 文本标签还干净 | 全保留，多发言人面反而更好做 | 技术上最忠实「常驻群友」场景；但国内面试官触达差（TG/DC 不便），产品传播弱 |
| **QQ 自连** | 大：要重做 dsh-qqbot 适配器已解决的协议/凭据层 | 全保留 | 重复造轮子，零新增能力，不划算 |

## 成本评估（诚实版）

用户预期「不挂宿主 = 更省」——**部分成立，要拆开看**：

**真省的**：
- 宿主侧 prompt 开销消失（dsh 自身 system prompt/工具段不再计费）
- 拿到**全链路字节级 prompt 控制权**：前缀缓存、注入精简、模型选择全自由——陪伴场景不强求旗舰模型，chat 模型可降档省钱
- 蒸馏调度自由：可攒批/闲时跑/与回复调用合并策略，不受宿主 turn 边界约束
- 部署少一层 cordis 运行时依赖；演示流量天然低（几十轮/天 vs 线上 250），月账单绝对值会低很多

**不省的**：
- 每轮 chat 推理仍是最大单项——它只是从 dsh 账单挪到自己账单，结构性成本不变
- 「不挂宿主」省的是依赖和运维，不是 token 单价
- 真正的成本是**工程量**：channel 适配 + 壳层 + 第二套部署/备份面

**结论**：token 口径小幅省或持平，赢在端到端成本可控 + 单进程可跑。成本叙事从「插件侧有界」升级为「全链路账单自有、单轮成本可报数」——这本身是简历加分点。

## 简历价值评估

**不要写成第二个独立项目**。陪伴聊天 agent 是最泛滥的 demo 品类（每个 LangChain 教程都在做），单独列条目反而稀释主项目。

**该当主项目的证据点用**——它补上当前简历叙事唯一「声称但未证」的环节：

- 现叙事讲「宿主无关认知内核」，但只有架构论证（零 ctx 引用），没有第二 deployment 事实
- 落地后简历可写：「内核已在 dsh 之外落地第二 deployment（可公开体验的陪伴 agent），验证宿主无关设计」——把 claim 变 evidence
- 附带独占卖点：**面试官可以直接玩**（现在没法让面试官进你的 QQ 群，demo 链接是作品集级资产）+ 端到端成本数字全自有 + 主动开口（自己的发送路径，无需宿主 intent 权限——这反而是 standalone 比 dsh 侧更容易做的一点）

## 风险与约束（继承 roadmap 诚实条款）

- **场景筛查仍生效**：陪伴 = 常驻陪伴设计（会话延续性 + 主动开口），不是套个聊天页就算
- **第二部署 = 第二维护面**：core API 未稳前，每次内核改动两个 deployment 都要跟（继承「不为 hypothetical 宿主铺面」精神——这次是真需求所以成立）
- **身份层非阻塞**：standalone 用全新 brain-data 目录，绕开存量数据归一化战役；self 分轨只影响「将来要不要人设切换」，最小形态单固定人设即可
- **dsh 仍 first-class**：陪伴 agent 是第二 deployment，不是迁移——dsh 群继续当试验田，新机制仍先在 dsh 验证再下沉（除非该机制本身为陪伴而生，如主动开口）

## 用户澄清的定位（2026-11-09 追问）

- **不为接 QQ 而接 QQ**——QQ 接入只是可选拓展项，不是卖点；「QQ+腾讯官方插件背书」的卖点已由当前项目吃完
- **竞品存在、不比新颖**——陪伴 agent 市面已有竞品，本方向价值不在「没人做过」
- **主要价值三条**：
  1. **学习载体**——把正在学的 Agent 知识用起来（自主 agent loop、tool use、主动开口、长期记忆质量迭代），插件形态学不到这些
  2. **发扬 brain 核心设计**——类脑记忆生命周期只是众多解法之一，但「蒸馏→遗忘→巩固 + 画像 + 情绪 + 可观测可审计」的组合仍然少见；陪伴 = 长期关系 = 记忆质量即产品，是最能放大这套设计的场景
  3. **谈资**——AI 工具开发经验 + 开发中的思考决策链，不是再凑一个简历条目
- **硬性要求：不是玩具**——用户原话「demo 玩具根本没有任何意义」

### 「不是玩具」的推论（评估补充）

玩具与否不取决于工程质量，取决于**有没有真实使用**：dsh 侧之所以产生好故事（污染事故→清洗链、成本审计→优化），全因真实群友每天在聊。陪伴 agent 若没人每天说话，一个月内退化为玩具。所以 channel 问题的本质不是简历，是**日活从哪来**——自用 dogfooding（自己每天聊）是成本最低的真实使用来源，也天然契合「陪伴自己」的产品定义。

### 差异化叙事修正

不是「又一个陪伴 agent」，而是「**记忆可观测的陪伴 agent**」——市面陪伴产品的记忆是黑盒，brain 的脑图/ops 流水让「它怎么记住你、现在什么心情」成为产品功能本身。这个 hook 市面确实少见，也是学习和谈资的共同落点。

## 建议 MVP 形态（修订）

```
独立目录（如 companion/，复用 src/brain 内核 file/workspace 依赖，不复制代码）
  ├─ 单固定 persona + 全新 brain-data 目录（与 dsh 实例隔离，绕开存量身份战役）
  ├─ chat loop：assemble → chat LLM → reply → ingest/endOfTurn
  ├─ web 聊天页（自用 dogfooding 主通道；挂现有 node:http 风格服务）
  ├─ 主动开口：cron 生成 + 页面打开时补达（自有发送路径，无需宿主 intent）
  └─ 预留 channel 接口：QQ/TG 适配器后置为可选拓展，不为 hypothetical 渠道铺面
```

## 结论（2026-11-09 两轮收敛后）

- **方向成立**：standalone 陪伴 agent 是 brain 内核的自然第二 deployment，天级壳层工程量，技术上无阻塞
- **定位**：学习载体（自主 agent loop / tool use / 主动开口 / 陪伴 eval）+ 发扬类脑核心设计 + 谈资；不作独立简历条目，作为主项目叙事强化（宿主无关 claim → evidence + 面试官可体验 + 端到端成本自有）
- **差异化 hook**：「记忆可观测的陪伴」——脑图/ops 流水从产品功能层面区别于黑盒记忆的市面陪伴产品
- **日活来源（用户拍板）**：两者都要、自用偏多 → web 自用通道先行，channel 接口预留，QQ/TG 公网后置
- **成本口径**：token 小幅省或持平；价值在端到端成本可控与部署独立，非结构性省钱
- **dsh 仍 first-class**：第二 deployment 非迁移，新机制仍先在 dsh 验证再下沉（陪伴原生机制除外）

**后续**：若启动实现，另建任务做 MVP 设计（壳层结构、persona 选型、主动开口策略、陪伴质量 eval 定义）。

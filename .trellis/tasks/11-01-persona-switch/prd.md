# 脑图多版本人设切换与鲸鱼娘温柔版

## Goal

在脑图中保留并管理现有人设，同时把用户提供的《鲸鱼娘群友人设-温柔版.md》作为可选择的人设，选择后让机器人使用所选人设，而不是覆盖并丢失原版本。

## Confirmed Facts

- 2026-11-01 用户提供文件 `/Users/somehow/dev/prompt/鲸鱼娘群友人设-温柔版.md`；文件是完整的鲸鱼娘群友温柔版人格内核，包含身份、说话风格、群聊判断、边界及情境参考。
- 当前只有单份人格文本：`BrainStore.personaText`、`persona.md`、`/api/persona` GET/POST；脑图“人格内核”只有编辑框和保存按钮。保存写入 store 并经回调写 `persona.md`，运行时 `Brain.persona()` 读取 store。
- 启动读取优先级为 `persona.md > store > 旧插件 groupPrompt 迁移（若存在）> 配置/默认`；迁移旧数据时不能丢掉已经编辑过的人设。`/api/export` 与脑图“备份迁移”均使用单个 `persona` 字段，导入也沿用单字段。
- 这是跨存储、启动、HTTP、页面和备份的变更；用户已同意建立本任务进入规划。

## Requirements

- R1 保留现有人设，新增上述温柔版人设作为可选项；不得静默覆盖正在使用的现有人设。
- R2 脑图提供可见的当前人设和切换入口；切换后机器人后续回复使用被选择的人设，重启后仍保持所选项。
- R3 可以在脑图新增、命名、编辑多个自定义人设；编辑一个人设时保持其他人设不变，并能切回先前版本。切换前未保存的编辑必须有提示，不可静默丢失。
- R4 现有单份人设数据与备份继续可用；新的人设数据要有可恢复途径。
- R5 同一个机器人实例共用一份当前人设；切换即时作用于随后新组装的回复，不更改已经在进行中的回复或历史消息。

## Acceptance Criteria

- [ ] 在已有单份人设的环境启动后，原文仍可读，温柔版可见且可选择，且不自动替换原文。
- [ ] 从脑图切换后，当前人设显示与注入文本一致；重启后保持选择，来回切换内容不丢失。
- [ ] 能在脑图新增命名的人设，保存修改并切换；切换、定时刷新时未保存的编辑不会被静默覆盖，且另一个人设内容不变。
- [ ] 旧备份可导入；新备份还原后仍可切换人设。
- [ ] 非法或空白人设、无效的切换目标均不会改变当前人设。
- [ ] `npm test`、`npm run typecheck`、`npm run build` 通过。

## Out of Scope

- 不改变记忆、态度、画像、群聊是否发言等现有逻辑；不做按群或按用户自动选择人设。
- 暂不提供删除人设、重命名历史内核的自动推断、外部 `.md` 文件任意路径导入、独立人设商店；新增/改名可通过脑图操作完成。
- 不在规划确认前向用户的运行中数据目录写入或改变当前启用人设。

## Key Decisions

- 2026-11-01 用户选择推荐的“可新增、命名、编辑多个自定义人设”而不是仅两个固定选项。
- 保留当前人设为默认启用；温柔版作为预置可选项，用户主动切换才生效。切换范围为整个机器人实例，不做会话级覆盖。

## Resolution（2026-11-01）

- **遇到了什么问题**：原脑图只有一份可覆盖的人格内核，无法在旧人设与鲸鱼娘温柔版之间来回切换；旧备份也只携带一份人设。
- **怎么解决的**：将提供的 Markdown 原样内置为非自动启用的预置版本；在 JSONL/快照中持久化命名人设列表与活动 ID，兼容旧人设事件、`persona.md`、v1 备份；提供脑图新增/编辑/切换、API 与全量备份，活动文本继续镜像到 `persona.md`。
- **后续优化方向**：按群切换、删除人设、页面上传 Markdown、浏览器全交互回归测试均留待后续；当前不改变发言触发机制。
- **什么时候干的**：2026-11-01。
- **Key Decisions**：现有人设不被覆盖也不自动切换；切换为全局，之后新回复组装即用；保留旧单字段 API 与备份兼容。
- **验证结论**：`npm test` 72/72、`npm run typecheck`、`npm run build`、`npm pack --dry-run` 内置文件检查和原 Markdown 字节一致性检查均通过；未对真实机器人发消息。提交和两层归档待完成。

# 验收分级指南（Verification Tiers）

> 每个改动在动手前就决定「用哪一级证据关闭」。代码证据随提交关闭；行为证据部署前关闭；生产证据进台账跨任务存活。
> 来源：`tasks/11-14-acceptance-registry` 立台账，11-14～11-18 五次走查（ACC-03/06 通过、ACC-08 豁免）跑通后沉淀。

## 三级证据

| 级 | 证明什么 | 工具 | 何时关闭 |
| --- | --- | --- | --- |
| T1 代码 | 函数/契约在给定输入下正确 | `npm run typecheck` · `npm test` · `npm run eval`（检索） | 提交即关（pre-commit + CI 自动跑） |
| T2 离线行为 | LLM 在生产等价 prompt 下的行为没有回归 | `npm run eval:prompt -- --base <上次部署 commit>` | 部署前关；疑似回归加大 n 复核后才算 |
| T3 生产实证 | 真实流量 / 真实数据下机制生效 | `.trellis/acceptance.md` 登记的命令/查询 | 证据达阈值才关；归档前必须**登记**，不要求**通过** |

## 改动 → 最低证据级

| 改动类型 | 最低级 | 备注 |
| --- | --- | --- |
| 纯函数 / 解析 / 存储 op | T1 | 新 op 走消费点审计（`spec/backend/index.md`） |
| 检索 / 排序参数 | T1（eval） | lexical 4 FAIL 为 ACC-08 豁免基线，勿当回归 |
| persona.md / channelStyle / 蒸馏 prompt | T2 + T3 | T2 拦明显回归；T3 等真实样本证明修复泛化 |
| 前端 / 管理端 | T1 + 手动走查截图 | 移动端按 375/768/1440 三档 |
| 部署流程本身 | T3 | 一次正式发布 + 一次回滚演练（ACC-13） |

## 判定纪律

- **能前移就前移**：T3 长期待触发（> 14 天无样本）→ 复审能否构造样本降到 T2（写 prompt eval 用例）或用故障注入验证；体检脚本会标出陈龄。
- **T2 不替代 T3**：离线 prompt 缺宿主 identity/tools 段，只做 base vs head 相对比较。
- **样本量写进阈值**：「N=3/5」式记录，单次走查只记情况不闭环。
- **证伪即打回**：T3 出现反例 → 台账标「打回」，回任务修，不在台账里讨论修法。

## Scenario: brain persona selection and compatibility

### 1. Scope / Trigger

Changes to `dsh-qqbot-brain` persona storage, HTTP endpoints, startup loading or backup must keep all four paths consistent: JSONL/snapshot → active persona → `persona.md` mirror → `/brain` and prompt injection. A page-only switch does not switch the bot.

### 2. Signatures

- `BrainStore.createPersona(name, text, id?)`, `savePersona(id, name, text)`, `activatePersona(id)`, `activePersonaId()`, `listPersonas()`.
- `Brain.persona()` and `Brain.assemble(...).persona` always read the active text.
- `GET /brain/api/personas`, `POST /brain/api/personas`, `PATCH /brain/api/personas`, `POST /brain/api/personas/activate` use fixed paths so the host webServer can register them explicitly.

### 3. Contracts

- `GET /api/personas` returns `{activeId: string, personas: [{id,name,text}]}`; POST accepts `{name,text}`; PATCH accepts `{id,name,text}`; activate accepts `{id}`. Existing `/api/persona` still reads/writes active text.
- The `legacy` ID retains old persona text; `whale-gentle` is the bundled optional preset; custom IDs are generated by the server. Do not silently activate the preset on upgrade.
- v1 backup retains `persona` (active text) and optionally includes `personas` and `activePersonaId`; snapshot and JSONL ops retain both list and selection. `persona.md` remains the active-text mirror: external edits win at startup; API updates/imports must sync it. `npm run build` must copy the bundled Markdown to `dist/setup/`.

### 4. Validation & Error Matrix

- Empty name/text, overlong name (>80) or text (>50,000), malformed personas list → 400 without modifying the selected persona; unknown ID → 404.
- Replace import validates persona list and active reference before `reset`; merge skips conflicting IDs, keeps local activity; replace restores the backup activity.
- All API calls respect `http.token` via query or `x-brain-token` header; wrong/missing token → 401.

### 5. Good / Base / Bad Cases

- Good: save two named entries, activate one, restart, and get the same active text and alternative; backup/restore retains both.
- Base: old `persona.md` and old `{persona: string}` backup migrate into `legacy`, preserving existing content.
- Bad: page-only selection, new prompt text written straight to `persona.md` without updating store, or backup page exporting only `state.persona` loses version history.

### 6. Tests Required

- `test/brain.test.ts`: old snapshot/ops replay, save/switch/flush/restart, merge and replace backup, invalid replace does not clear current.
- `test/http.test.ts`: token, create/patch/activate, `persona.md` synchronization, startup preset equality and old-file priority.
- `test/page.test.ts`: inline script syntax, dirty draft survives 15-second refresh.

### 7. Wrong vs Correct

- Wrong: update `/api/persona` text but leave the old `persona.md`, then restart; the file overrides the update.
- Correct: persist the active ID and content, mirror the active text after API changes and import, then verify `Brain.persona()` and startup return the same value.

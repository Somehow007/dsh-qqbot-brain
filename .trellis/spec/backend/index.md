# dsh-qqbot-brain 后端约定

- TypeScript ESM，零运行时依赖（2C2G 服务器约束）；相对导入带 `.ts` 扩展名。
- 类型导入必须 `import type`（Node strip-types 模式兼容）。
- 禁用构造器参数属性（`constructor(private x)`）——Node 类型擦除不支持。
- 宿主交互用结构化投影接口（仿官方插件），不硬依赖 cordis 类型。
- 测试：`node --test test/brain.test.ts`（Node 原生跑 TS）；构建 `npx tsc -p tsconfig.json`。
- 记忆检索算法：char 1-3gram TF-IDF cosine（文本先归一化：小写化 + `[^\p{L}\p{N}]` 全去掉——标点不去会把 bigram 切断，如「橘猫，名叫年糕」对「猫叫什么」cos=0）；命中先过 `minCosine` 门槛（默认 0.04，0=不过滤，离线校准值见 tasks/10-31-retrieval-lexical-fix），再按 score=α·cos+β·R+γ·imp/5 排 topK，不足不凑数（可返回空）；R=e^(-t/S)。
- `Brain` 的 `config` 是 `Partial<BrainConfig>`：插件侧改检索/巩固参数时必须显式并入（`config: { ...cfg.retrieval, consolidateMinAgeDays, consolidateMinNotes }`）——`cfg.retrieval` 曾漏接导致配了不生效，新增 BrainConfig 字段时同步检查 src/index.ts 装配与 src/config.ts 的 RetrievalConfig/DEFAULT_CONFIG。嵌套对象（如 `deepRecall`）需要深合并：Brain 构造器与 index.ts 装配各做一层 `{...DEFAULT, ...partial}`，半覆盖不丢默认字段。
- 主动召回两层（迭代C）：`Brain.search(sessionId, query, opts?, queryVec?)` 是纯检索原语——可见池与 assemble 逐字同口径（trackVisible+scopeVisible+absorbed），返回 `ScoredNote[]`（rel/score/relSrc），不 reinforce（唤起语义归调用方）；opts 支持 `limit/kinds/crossSession/minCos/minEmbedCos`。变体池（kinds/crossSession）必须用独立 `indexKey` 命名空间（`__search__{x|s}:{sid}:{kinds}`），否则命中旧池 TF-IDF 索引静默串味。深挖门控 `maybeDeepRecall`（assemble 内）：`RECALL_INTENT_RE` 意图词 ∧ lane-1 真相关命中（rel≥路径强化阈）<`weakRelHits` 双门触发，`deepRecall.{minCos=0.07,minEmbedCos=0.55}` 严于 lane-1 地板（深挖行权威口径呈现宁缺毋滥），与已注入 id 去重后 ≤`limit` 条进 `deepRecallLines`→`brain:deeprecall` section（order 10325）；picked 条目按 lane-1 同规则 reinforce。`injectDeepRecall=false` 时 index.ts 将 `deepRecall.enabled` 一并置 false（不为不注入的 section 白付检索成本）。调试口 `/api/query?depth=1` 透传深挖参数返回 rel/score/relSrc 明细。
- 记忆 kind 三型：episodic 情景 / semantic 语义 / attitude 态度（角色对人·事·话题的立场，content 规范「对<对象>：<立场>」）。attitude 不进语义巩固输入；含当前发言人昵称的 attitude 在 assemble 中保底唤起（≤3 条），不占 topK。
- 新增记忆 kind 或 JSONL op 时同步改：types.ts 联合、distill 解析、http.ts 入参、page.html 的 kindLabel/KIND_GLYPH/REGION/三个 kind select。
- 三轨记忆模型（角色→人设两级）：记忆分世界轨（非 attitude 且 self≠true，全角色共享，personaId 只是来源标签）与自我轨（attitude 恒自我轨 + self:true，仅同 characterId 可见）；情绪态按 character 隔离、不匹配读中性、同角色版本共享。`self` 三态：true 自我轨 / false 显式世界轨（启发式不覆盖，手动修正语义）/ 缺省走 `isSelfContent` 启发式（剥引号后含「我」）；`PersonaEntry.characterId` 缺省=人设自身 id，whale 系三版本归 'whale'（常量在 types.ts）。可见性一律读时判定（`Brain.trackVisible`/`trackKeyOf`/`characterOf`），切换人设不删不换数据；判重/归并/巩固喂料都必须过 trackKey/trackVisible 守卫，新增召回或归并路径时同样检查。蒸馏批次人设在 endOfTurn 开头钉住（batchPid），批内 notes/emotion/画像/profile 写回统一用它，防运行中切换人设造成归属错乱。语义巩固按角色分批（`consolidationBatches`）：每条 episodic（自我轨与世界轨同口径）按 `characterOf(notePersonaId)` 分组各跑一次，批内视角=批内人设众数——世界轨源**不得**并入会话众数角色批：批次视角决定提示词人设、情绪盖章与 LLM 判 self 产出的轨道归属，并入他角色批会让别角色视角消化世界事实、self 产出落错轨（F5 线上实锤）；小角色批凑不够 minNotes 延迟巩固=宁慢不错；全自我轨源批次的产出缺省继承 self:true（LLM 显式 self 含 false 优先于继承），防第一人称被改写成第三人称后漏标世界轨串味。
- `Brain.importData` 导入成功后对全部无向量条目 fire-and-forget `embedNotes`（人设种子包不带 embedding，不补则只能等重启回填）；向量回填 interval 常驻低频清扫不自清——无待补条目时仅本地扫描零 API 成本，embed 瞬时失败自愈。
- 画像按人存储：键 `u:<openid>`（发言人 tag 带 openid）/ `sess:<sessionId>`（兜底，私聊 sessionId 即用户派生）。主键/actor 拆分走 `src/brain/identity.ts`；store 兼容旧裸 sessionId 键与字符串值（load/apply 时迁移）；蒸馏 `profiles:[{actor?,text}]` 结构化输出，旧 `profile` 字符串字段仍解析为会话级。注入时发言人 openid 取个人画像置顶，sess 画像标「会话画像」次之；attitude 保底唤起不限本会话（对人记忆跟人走）。页面 `/api/profiles` 按人出卡，sess 卡由 `/api/sessions` 出。
- 画像身份键必须经真实发言人记录校验（store.speakers()：记忆 actor + 已有 u: 键 + 本轮 actor）——LLM 会幻觉/抄错 openid，出现过同名双卡 bug；openid 可信→u: 键、昵称唯一匹配→校正、都不匹配→退化 sess: 不造幽灵人。
- 画像按人共享、对所有角色注入：涉及与角色的关系必须**点名角色**（「与鲸鱼娘是恋人」），禁泛指「角色/我」——泛指关系句换角色后会被读成自己的（线上 sess 画像混写 whale「主人」与 ye「师姐」致串味）；角色视角感受落 attitude。口径集中在 distill.ts `PROFILE_RELATION_RULE`，蒸馏/巩固/撰稿三路引用，审核路保留点名；新增画像写路径必须同样引用。
- 渠道表达口径 `brain:style`（order 10250）：宿主 dsh-tool-web 注入「cite URLs as markdown links」（tool:web_fetch order 2100，在 persona 80 之后），QQ 不渲染 markdown 且会把搜索回合拉成跨人设同一骨架——插件以静态段覆盖**格式**部分（安全语义不动）。必须排在 2100/persona-suffix 10200 之后、易变段 10300 之前（既压得住又留在稳定前缀）；正文 `channelStyle` 按渠道配置（companion 网页端另配），空串或 `injectChannelStyle=false` 不注入。人设包另需写「查资料/答知识题时」的角色化交付方式——只靠格式约束解决不了跨人设同质化。
- 蒸馏 prompt 的「现有画像」段（buildDistillPrompt 第 6 参）喂 sess+涉及发言人的旧画像，画像增量修订防漂移；consolidate 走同一 existingProfiles 收集。
- 画像内容边界不能只靠蒸馏 prompt 的「不要写近期课表」字样：旧画像会循环进入后续 prompt。endOfTurn/consolidate 的画像都必须通过 Distiller.reviewProfiles（旧文+草稿，按 index 对齐，失效时保持旧画像）；首次涉及旧画像也需审核。审核为空可用空 profile op 删除旧画像；请用实际落盘/重放测试而非只测 prompt 字符串。不要用「课表/明天」关键词硬删稳定的习惯或身份背景。二次 LLM 有成本，线上需观察效果。
- 蒸馏/LLM 调用必须可注入 fetch、可配置关闭、失败静默不阻塞回复。
- 蒸馏 emotion 的 `mood` 字段是受控枚举（types.ts `MOODS`：平静/开心/兴奋/害羞/好奇/委屈/炸毛/记仇/难过），page.html `EMO_BUCKETS` 的 name 与其一一对应；label 仍是自由短语供注入。解析时非枚举值丢弃（回退 v/a 推断），改动 MOODS 时必须同步 prompt 文案、page 桶表与测试。
- 多人设存储、`/api/personas` 契约、`persona.md` 镜像和备份兼容的完整检查见 [后端质量约定](./quality-guidelines.md#scenario-brain-persona-selection-and-compatibility)。
- 记忆初始强度可被 `strengthBoost`（NoteDraft，入库 clamp [0.1,3]）加权：Brain.emotionBoost 按形成时情绪 |v|·a 给 1.0~1.5——强情绪记忆更难忘；情绪只加权 strength，不动 LLM 自评的 importance。
- `/api/state` 边集缓存键 = `sessionId|store.graphVersion|persona`；graphVersion 仅在 add/update/del/merge/reset/embed 时递增（reinforce/emotion 等不动边集的写不计），改动影响边集的 op 时同步检查该集合。
- `MOOD_VALENCE`（types.ts）是 mood→效价符号表；mood 与 v 符号矛盾（|v|>0.3）时 endOfTurn 打 debug 日志而不改写——观测期，证据充分后再决定是否收紧为解析层过滤。
- 时间渲染统一走 `src/brain/time.ts`：`formatStamp`（convo 行 `[YYYY-MM-DD HH:mm]`）/ `formatShort`（轮内多消息 `[HH:mm]`）/ `formatClock`（当前时刻行，含星期与时区标签）/ `ageLabel`（记忆形成年龄 `N分钟前/N小时前/N天前`）；时区一律取 `cfg.timeZone`（默认 `DEFAULT_TIME_ZONE='Asia/Shanghai'`，types.ts 单一出处），非法时区降级系统时区不抛错。宿主 `[Chat history]` 无时间戳属官方包渲染层行为，插件侧不补。
- **QQ 平台 C2C 内容风控边界**：用户消息先过腾讯安全审核再到机器人 WebSocket——越线消息（黄色/露骨）在入站侧被吞，不派发、无本地日志、发送端无回执。表现为「机器人不理人」但实为未收到；与 LLM 拒答/服务宕机的区分：会话转录（`~/.dsh/sessions/**/session.v4.jsonl.zstd`）出现**零事件死窗**且前后消息正常 + 同期其他会话在线即可定性。拦截非简单关键词匹配（更露骨的长文可能到达，密集连发更易触发），腾讯黑盒不可观测。出站侧同样存在审核，发送失败走 `logger.error('im-qqbot: flush failed')` → stdout → `/var/log/dsh/qqbot.log`；API 返回成功不代表终端送达（异步审核）。排查记录见 `tasks/archive/2026-11/11-02-qqbot-nsfw-message-drop`。
- **standing intents（迭代D prospective memory）**：`IntentEntry`（types.ts）两型——`event`（match.text/actor 子串或 `/…/flags` 正则，双给 AND）/`time`（`fireAt` 一次性与 `dailyAt` 'HH:mm' 每日复发互斥恰一）。生命周期 op：`intent-add`/`intent-update`（patch null=清除，可变字段白名单）/`intent-fire`（**op 自带结果态** firedCount/cooldownUntil/status，重放确定性不重算）/`intent-del`；快照 `intents[]` 数组、reset 清空、导出导入含 intents（merge 按 id 去重）。intent op 只 bump `version` 不进 `graphVersion` 名单（不影响记忆边集/检索索引）。触发评估确定性零 LLM：event 型在 `Brain.ingest` 内对 `via==='user'` 的 turn 即时匹配（`match.text` 只测 userText 不含 contextText 环境消息；`it.sessionId` 限定会话）；time 型由 `tickIntents` 评估——ingest 顺带调一次 + 插件 60s `setInterval` 兜底，幂等。终态规则：`expiresAt` 过期→expired、`firedCount>=maxFires` 或 fireAt 一次性→fired（`intentGate` 对全部 pending 清扫，不依赖消息到达）；`cooldownUntil=lastFiredAt+cooldownMs` 防刷屏；dailyAt 场次须 `>createdAt`（创建当天不补打）且 `lastFiredAt<当日场次`（不补打漏掉的天数）。`ingest` 返回本轮 fired `IntentEntry[]`——dsh 捕获侧忽略，companion 壳层消费生成主动消息。HTTP `/api/intents` CRUD+`/tick`（tick 先于 `<id>` 动态匹配显式判断），`/api/state` 的 graph() 带 `intents` 全量字段。match 正则创建/更新期编译校验（`compileMatchPattern`，非法 throw 400），运行期 `matchPatternCache` 上限 200 防无界增长。
- **provenance/session-kind（迭代D）**：`Turn.via` 三态 `'user'`(缺省)/`'agent'`/`'system'`——agent=角色主动开口、system=系统事件。`endOfTurn` 门禁：整批无 user 轮次→跳过蒸馏+摘要（角色自己的话不当用户事实归档，反而省 LLM 调用）；混合批次进 distill 的 `convoLines`（distill/digest 共用）把 agent/system 渲染成单行「角色（主动开口）/系统：…」并在 prompt 口径段声明「不是用户发言」。`withBoundSpeaker` 只给 user 系轮次补绑定昵称。`MemoryNote.source` 四值 `MEMORY_SOURCES`：蒸馏路径恒 `'user'`、`Brain.addNote`（脑图/API）缺省 `'manual'`、导入缺省 `'import'`（自带保留）、巩固同质继承（源批同 source→同源，混合→'user'）；sanitizeNote 白名单校验透传，旧数据缺省视同 user 系。

# dsh-qqbot-brain 后端约定

- TypeScript ESM，零运行时依赖（2C2G 服务器约束）；相对导入带 `.ts` 扩展名。
- 类型导入必须 `import type`（Node strip-types 模式兼容）。
- 禁用构造器参数属性（`constructor(private x)`）——Node 类型擦除不支持。
- 宿主交互用结构化投影接口（仿官方插件），不硬依赖 cordis 类型。
- 测试：`node --test test/brain.test.ts`（Node 原生跑 TS）；构建 `npx tsc -p tsconfig.json`。
- 记忆检索算法：char 1-3gram TF-IDF cosine（文本先归一化：小写化 + `[^\p{L}\p{N}]` 全去掉——标点不去会把 bigram 切断，如「橘猫，名叫年糕」对「猫叫什么」cos=0）；命中先过 `minCosine` 门槛（默认 0.04，0=不过滤，离线校准值见 tasks/10-31-retrieval-lexical-fix），再按 score=α·cos+β·R+γ·imp/5 排 topK，不足不凑数（可返回空）；R=e^(-t/S)。
- `Brain` 的 `config` 是 `Partial<BrainConfig>`：插件侧改检索/巩固参数时必须显式并入（`config: { ...cfg.retrieval, consolidateMinAgeDays, consolidateMinNotes }`）——`cfg.retrieval` 曾漏接导致配了不生效，新增 BrainConfig 字段时同步检查 src/index.ts 装配与 src/config.ts 的 RetrievalConfig/DEFAULT_CONFIG。
- 记忆 kind 三型：episodic 情景 / semantic 语义 / attitude 态度（角色对人·事·话题的立场，content 规范「对<对象>：<立场>」）。attitude 不进语义巩固输入；含当前发言人昵称的 attitude 在 assemble 中保底唤起（≤3 条），不占 topK。
- 新增记忆 kind 或 JSONL op 时同步改：types.ts 联合、distill 解析、http.ts 入参、page.html 的 kindLabel/KIND_GLYPH/REGION/三个 kind select。
- 画像按人存储：键 `u:<openid>`（发言人 tag 带 openid）/ `sess:<sessionId>`（兜底，私聊 sessionId 即用户派生）。主键/actor 拆分走 `src/brain/identity.ts`；store 兼容旧裸 sessionId 键与字符串值（load/apply 时迁移）；蒸馏 `profiles:[{actor?,text}]` 结构化输出，旧 `profile` 字符串字段仍解析为会话级。注入时发言人 openid 取个人画像置顶，sess 画像标「会话画像」次之；attitude 保底唤起不限本会话（对人记忆跟人走）。页面 `/api/profiles` 按人出卡，sess 卡由 `/api/sessions` 出。
- 画像身份键必须经真实发言人记录校验（store.speakers()：记忆 actor + 已有 u: 键 + 本轮 actor）——LLM 会幻觉/抄错 openid，出现过同名双卡 bug；openid 可信→u: 键、昵称唯一匹配→校正、都不匹配→退化 sess: 不造幽灵人。
- 蒸馏 prompt 的「现有画像」段（buildDistillPrompt 第 6 参）喂 sess+涉及发言人的旧画像，画像增量修订防漂移；consolidate 走同一 existingProfiles 收集。
- 画像内容边界不能只靠蒸馏 prompt 的「不要写近期课表」字样：旧画像会循环进入后续 prompt。endOfTurn/consolidate 的画像都必须通过 Distiller.reviewProfiles（旧文+草稿，按 index 对齐，失效时保持旧画像）；首次涉及旧画像也需审核。审核为空可用空 profile op 删除旧画像；请用实际落盘/重放测试而非只测 prompt 字符串。不要用「课表/明天」关键词硬删稳定的习惯或身份背景。二次 LLM 有成本，线上需观察效果。
- 蒸馏/LLM 调用必须可注入 fetch、可配置关闭、失败静默不阻塞回复。
- 蒸馏 emotion 的 `mood` 字段是受控枚举（types.ts `MOODS`：平静/开心/兴奋/害羞/好奇/委屈/炸毛/记仇/难过），page.html `EMO_BUCKETS` 的 name 与其一一对应；label 仍是自由短语供注入。解析时非枚举值丢弃（回退 v/a 推断），改动 MOODS 时必须同步 prompt 文案、page 桶表与测试。
- 多人设存储、`/api/personas` 契约、`persona.md` 镜像和备份兼容的完整检查见 [后端质量约定](./quality-guidelines.md#scenario-brain-persona-selection-and-compatibility)。
- 记忆初始强度可被 `strengthBoost`（NoteDraft，入库 clamp [0.1,3]）加权：Brain.emotionBoost 按形成时情绪 |v|·a 给 1.0~1.5——强情绪记忆更难忘；情绪只加权 strength，不动 LLM 自评的 importance。
- `/api/state` 边集缓存键 = `sessionId|store.graphVersion|persona`；graphVersion 仅在 add/update/del/merge/reset/embed 时递增（reinforce/emotion 等不动边集的写不计），改动影响边集的 op 时同步检查该集合。
- `MOOD_VALENCE`（types.ts）是 mood→效价符号表；mood 与 v 符号矛盾（|v|>0.3）时 endOfTurn 打 debug 日志而不改写——观测期，证据充分后再决定是否收紧为解析层过滤。
- 时间渲染统一走 `src/brain/time.ts`：`formatStamp`（convo 行 `[YYYY-MM-DD HH:mm]`）/ `formatShort`（轮内多消息 `[HH:mm]`）/ `formatClock`（当前时刻行，含星期与时区标签）/ `ageLabel`（记忆形成年龄 `N分钟前/N小时前/N天前`）；时区一律取 `cfg.timeZone`（默认 `DEFAULT_TIME_ZONE='Asia/Shanghai'`，types.ts 单一出处），非法时区降级系统时区不抛错。宿主 `[Chat history]` 无时间戳属官方包渲染层行为，插件侧不补。
- **QQ 平台 C2C 内容风控边界**：用户消息先过腾讯安全审核再到机器人 WebSocket——越线消息（黄色/露骨）在入站侧被吞，不派发、无本地日志、发送端无回执。表现为「机器人不理人」但实为未收到；与 LLM 拒答/服务宕机的区分：会话转录（`~/.dsh/sessions/**/session.v4.jsonl.zstd`）出现**零事件死窗**且前后消息正常 + 同期其他会话在线即可定性。拦截非简单关键词匹配（更露骨的长文可能到达，密集连发更易触发），腾讯黑盒不可观测。出站侧同样存在审核，发送失败走 `logger.error('im-qqbot: flush failed')` → stdout → `/var/log/dsh/qqbot.log`；API 返回成功不代表终端送达（异步审核）。排查记录见 `tasks/archive/2026-11/11-02-qqbot-nsfw-message-drop`。

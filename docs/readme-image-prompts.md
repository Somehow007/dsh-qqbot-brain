## 2. 单轮读写时序图 `docs/img/turn-sequence.png`

对应 ASCII 图的视觉版，讲清一轮对话里「读路径注入 → 回复 → 写路径蒸馏」的完整时序。

```
画一张 16:9（约 1600×900）的 UML 风格时序图，深色科技风：
深蓝背景（#0B1B33），生命线用细 cyan 竖线，消息箭头用亮色（白/青/琥珀区分读写），
扁平矢量，中文标签，文字精炼。

顶部横向排 6 条生命线（从左到右）：
「QQ 用户」「dsh-qqbot」「Brain 插件」「聊天 LLM」「蒸馏 LLM」「brain.jsonl 存储」

时序从上到下（每步一根带序号的箭头）：

1. 用户 → dsh-qqbot：「发消息（含昵称+openid）」
2. dsh-qqbot → Brain：「system-prompt/assemble 请求组装」
3. Brain → dsh-qqbot：「返回 7 个 section（人格/脉络/情绪/立场/记忆/发言人/时刻）」
4. dsh-qqbot → 聊天 LLM：「system prompt + 会话回放」
5. 聊天 LLM → dsh-qqbot → 用户：「人格化回复」
6. （虚线分隔，标注「轮末」）dsh-qqbot → Brain：「turn/end 触发蒸馏」
7. Brain → 蒸馏 LLM：「本轮对话 + 现有画像/记忆/情绪」
8. 蒸馏 LLM → Brain：「记忆草稿 + 情绪增量 + 画像草稿」
9. Brain → Brain 自身一条小回环：「画像二次审核」
10. Brain → brain.jsonl：「op 流水 + 快照更新」
底部补一条淡色支线：「/brain 脑图页 15s 轮询展示」从存储指向页面图标。

读路径（1-5）用青色箭头，写路径（6-10）用琥珀色箭头，一眼区分两个相位。
标题：「一轮对话的读写时序」。中文标签，每条消息文字 ≤15 字。
```

## 通用出图建议

- 一次只喂一条提示词；出图后先检查中文标签有没有错字，错了让 GPT 只改字不要重画布局（「保持布局，只把 xx 改成 yy」）。
- 若 GPT 反复写错中文，把提示词末尾加一句：「所有标签改用英文，中文词放括号内」或全英文标签版，我可以接受英文图。
- 图统一存 `docs/img/`（目录我来建）；交付时把文件名告诉我，我替换 `<!-- IMG-SLOT -->` 占位注释为 `<img>` 标签并校对引用。
